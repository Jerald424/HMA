================================================================================
APPENDIX — ERROR RESPONSE FORMAT (Standard)
================================================================================

All endpoints return errors in the following format:

{
  "error": {
    "code": "LEAVE_BALANCE_INSUFFICIENT",
    "message": "You do not have enough annual leave balance.",
    "http_status": 422
  }
}

Common HTTP status codes used:
  200  — Success
  201  — Created
  400  — Bad request / validation error
  401  — Unauthorized (token expired or missing)
  403  — Forbidden (access to another employee's data, or read-only field edit)
  404  — Resource not found
  422  — Unprocessable entity (business rule violation)
  500  — Internal server error


================================================================================
APPENDIX — SECURITY NOTES
================================================================================

  1. All tokens are JWT (RS256). Validate signature on every request.
  2. NDA must be signed before any other API call returns data (enforced at gateway).
  3. Screenshot restriction flag is returned at login; enforce at client SDK level.
  4. Payslip and document view URLs are signed & time-limited (10 min expiry).
  5. Employee can only access their own records. Cross-employee access returns 403.
  6. Bank detail changes trigger HR review workflow — not applied immediately.
  7. Force entry and payroll dispute requests are audit-logged with timestamps.
  8. Policy/handbook documents: downloadable=false must be enforced client-side AND server-side.
